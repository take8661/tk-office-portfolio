## 候補1：Codrops「Crumbled Paper」／ Paper Crumple (VAT)

- 記事：https://tympanus.net/codrops/2026/09/19/crumbled-paper-houdini-vat-threejs/ （著者 Toi Nagasawa／ITEM Inc.）
- ライブデモ：https://tympanus.net/Demos/PaperCrumble/ および https://paper-crumple-demo.pages.dev/
- **ソース実物（記事本文からはリンクが見えず、デモページのHTMLから特定）**：https://github.com/item-develop/paper-crumple-demo
  - stars 23／forks 6／最終push 2026-09-16。ビルド不要の静的ファイル一式（index.html＋src/*.js＋vat/）
  - 同梱素材：`vat/geo/vertex_animation_textures1_mesh.fbx`（1.2MB）、`vat/tex/vertex_animation_textures1_pos.exr`（1.7MB）。Houdiniを持っていなくても再生側は全部試せる（記事の記載通り）
- **ライセンス：MIT（確認済み）**
  - リポジトリに LICENSE ファイル実物あり。本文で「Copyright (c) 2026 nagasawa (ITEM Inc.)」のMIT全文を確認した。GitHub API の license 判定も MIT。
  - 別途、Codrops のライセンスページ（https://tympanus.net/codrops/licensing/ ）でも「downloadable demos は特記なき限り MIT」を確認済み。
  - 注意：デモ内のフォント（Caveat／Yomogi、Google Fonts）や紙面デザインは自前差し替え前提。VATデータ（FBX/EXR）自体は同リポジトリのMIT範囲内と読めるが、商用本番でそのまま使う場合は念のため著者表記を残す。
- 技術構成（実物確認）
  - three.js **0.160.1**（importmap、CDN）＋ cannon-es 0.20.0。素のJavaScript（React等なし）＝現行TK Officeサイト（単一HTML）の作りにそのまま移植しやすい。
  - Houdini Vellum でベイクした50フレーム／3,500点を、FBX＋EXRからCPUでデコードしてフレーム補間再生。逆再生・途中停止・再生位置へのイージング適用が可能（＝「動きが遅い」問題は再生速度とイージングをこちらで決められる）。
  - 移動・衝突は cannon-es の球剛体で近似。開閉中だけ頂点を更新し、転がっている紙は剛体のみ動かす設計で 50枚でも軽い。
  - 紙面デザインは `src/paper.js` が Canvas 2D で合成して CanvasTexture 化する構造 → **伝票の罫線・文字面への差し替えはこの1ファイルの置換で済む見込み**。
- **three.js 0.187.0 互換性（静的検証済み／描画実行は未実施）**
  - 使用している全 import 先（FBXLoader／EXRLoader／SSAOPass／OutputPass／EffectComposer／RenderPass／lil-gui）が 0.187.0 のCDNに存在（HTTP 200）することを確認。
  - 使用している THREE.* シンボル27種すべてが 0.187.0 の three.module.js に存在することを確認。
  - 最大の懸念だった FBXLoader の第2UV名は、0.160.1 と 0.187.0 で同一仕様（i=0→`uv`、i=1→`uv1`）。`paper-vat.js` は `getAttribute("uv2") || getAttribute("uv1")` のフォールバック付きなので壊れない。EXRLoader の `setDataType(THREE.FloatType)` も 0.187 に現存。
  - importmap を 0.187.0 に差し替えた試作コピーを `paper-crumple-0187/` に用意済み（このワークスペース内）。残る確認は「実際にブラウザで描画して開閉が崩れないか」の1点で、PC側での実行確認が必要。
- 伝票束への組み込み所見
  - そのまま使える形：丸まった伝票が1枚開いて読める、をヒーローの主動作にする。束は「丸まった紙の山＋順に開く数枚」で表現するのがデモの設計（50インスタンス・個別ジオメトリで独立開閉）に沿う。
  - 合わない可能性：VATの紙は1枚ものの矩形で、元の丸まり方が固定。伝票の縦長比率や「束がバサッとほどける」動きそのものは、このデータだけでは作れない。その場合は候補5で自前ベイクを作る。
  - 速度：再生はフレーム位置の補間なので、開く所要時間は自由に短縮できる。手描きイージング時代の「遅い・しょぼい」の構造的原因（動き自体が手作り）はこの方式では消える。

- 所見：伝票束には ✕。唯一の使い道は GSAP のスタッガー間隔（0.15秒刻み等）のタイミング設計の参考程度。

## 候補4：aatishb/drape

- リポジトリ：https://github.com/aatishb/drape （stars 255）
- **ライセンス：MIT（確認済み）**。LICENSE ファイル実物にMIT全文あり（Copyright © 2016 Aatish Bhatia, Demi Fang, Sigrid Adriaenssens）。GitHub API が「Other」と返すのは three.js 側ライセンスを併記した複合ファイルのためで、本文はMIT。
- 技術的な実態（実物確認）
  - 同梱 three.min.js は **REVISION "74"**（r74、2015年頃）。モジュール化以前のグローバルスクリプト構成（Detector.js／TrackballControls.js を script タグで読む）。`THREE.ParametricGeometry`、`gammaInput` 等、現行では削除・移転済みのAPIに依存。
  - 物理は Verlet 積分のバネモデル（構造／せん断／曲げバネ＋自己衝突回避オプション）。リアルタイム計算で、ベイクではない。
  - 紙ではなく布のシミュレーション。**塑性変形（折れ目が残る）がモデルにない**ため、伝票に使うと「布が垂れる」動きになり、リアリティ不足の再発リスクが高い。
- 0.187互換性：互換なし。使うなら clothphysics.js のバネ計算だけを抜き出してモジュールとして書き直す作業になる。
- 所見：組み込みは ✕。自前でリアルタイム紙シミュレーションを書く場合の数式・パラメータの参考として △。

## 候補5：Blender物理シミュレーション→MDD書き出し→three.jsシェイプキー再生

- 記事：https://tympanus.net/codrops/2025/08/20/exporting-a-cloth-simulation-from-blender-to-an-interactive-three-js-scene/ （著者 Joshua Guo、記事ID p=89147。プロトコルの `?p=89147` はこの記事で正しい）
- リポジトリ：https://github.com/codrops/BalloonButton （stars 7／最終push 2025-08-20）。`public/inflation.glb`（シェイプキー入り実データ）同梱。
- 手順の要旨（記事実物）：Blender の Cloth 物理をベイク → NewTek MDD アドオンで書き出し → MDD を読み戻してシェイプキー化 → glTF 2.0 (GLB) で Shape Keys＋Animations を含めて書き出し → three.js 側は GLTFLoader＋AnimationMixer で再生（クリックでリプレイ）。
- **ライセンス：要確認（候補2と同じ欠陥）**
  - README に「License [MIT](LICENSE)」とあるが **LICENSE ファイル実物なし**（404、API判定 None）。Codrops 一般ライセンスのMITが根拠候補。
  - ただしこの候補で使うのは「手法」自体（Blender標準機能＋MDDアドオン）であり、他者のコード／データを流用しなければライセンス問題は発生しない。サンプルの inflation.glb を本番素材として使う話ではない。
- 技術：three **0.179.1**、@react-three/fiber 9.3.0、@react-three/drei 10.7.3、React 19。5候補中で 0.187 に最も近い。再生側は素の three.js でも GLTFLoader＋AnimationMixer だけで書ける（React必須ではない）。
- 伝票束への所見
  - ○：伝票の実寸比率・束の枚数・ほどけ方を自分で設計してベイクできる唯一の無料ルート（Blender無料、Houdini不要）。「動きが実シミュレーション由来」という竹村さんの要求にそのまま応える。
  - 注意：記事の作例は「膨らむ布のクッション／ボタン」で、紙ではない。紙にするには Cloth の stiffness を高く、pressure は切る等のパラメータ設計が別途必要で、ここは試行錯誤が要る。シェイプキーはフレーム数×頂点数で GLB が太るため、頂点数とフレーム数の節約が前提。
  - 位置づけ：候補1のデータが伝票に合わない場合の生産ラインとして確保するのが正しい使い方。
